# These conventional commit types are shared across LVBT repositories.
#
# Three, deliberately. A subject line is read as a changelog entry by people
# who did not write the diff, and eight of the eleven types this list used to
# carry answered a question those readers never ask: which internal category
# the work fell into. `refactor`, `perf`, `style`, `test`, `build`, `ci` and
# `docs` all describe the same thing to them, upkeep, so choosing between them
# cost every author a decision that changed nothing downstream.
#
#   feat   a new capability a person can use or observe
#   fix    corrected behaviour
#   chore  everything else: tooling, tests, docs, build, CI, refactors, reverts
#
# The distinction that still earns its place is whether a changelog reader is
# affected. That one is kept; the rest belong in the body, where there is room
# to say what actually changed.
feat
fix
chore
